# Journal — 2026-11-04

## Session — 10:38

**Summary:** This session ran from 3 to 4 November and followed on from the 22:59 entry on 2 November. It was hands-on support while the developer set up two controls in a William Buck environment: ChoiceCounts' drill-through script on the SMSF Matter form, and GridFormatter on a table's main grid, the view a model-driven app opens from its left navigation. Both setup guides were then updated with what we learned.

**Discussion & decisions:**
- **ChoiceCounts drill-through:**
  - The form's On Load raised "`WBChoiceCounts.DrillThrough.onLoad` … method does not exist". I first suspected the function name's case, but the developer had only mistyped it in the message. The developer asked what `WBChoiceCounts` is: it's the namespace object the script creates for itself, not the control or the solution, so the error means the library never ran.
  - Clicking a count then logged `subgrid subgrid_atotask isn't on the form`, with control `wbsuper_atoragcount`. The console's subgrid list came back empty because the subgrid was on a tab that hadn't been opened.
  - The cause of both was the browser running an old cached copy of the web resource, with old names in `CONFIG`. It worked once the new copy loaded.
- **GridFormatter on views:**
  - The developer asked whether GridFormatter can style the view opened from the left navigation. It can, with no workaround: the table-level Power Apps grid control covers every view of the table. Rules can't target one view, so a view opts out by leaving one of a rule's columns out.
  - **Switch to classic** wasn't offered, so we used the classic solution explorer's `tools/solution/edit.aspx?id=<solution id>` URL. **Customize the system** was avoided because it edits the Default Solution, so the setting wouldn't reach UAT and prod. Microsoft Learn confirms the classic solution explorer is still the only place to set a table-wide grid control.
  - **Correction:** I told the developer to expect `[GridFormatter]` lines in the console. The control only logs problems, so a working grid is silent. Whether the control runs is now checked with the debug log.

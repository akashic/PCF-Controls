# Journal — 2026-10-25

## Session — 20:35

**Summary:** The developer raised three problems with how GridFormatter finds its rules: the `/` in the web resource name, the `.json` extension on a Script web resource, and the hard-coded `wb_` prefix, which meant a project on its own publisher couldn't create the file in its own solution. We designed a fix, recorded it as ADR-0005, opened #35, spiked the platform unknowns in `LowCode`, built GridFormatter 0.3.0, tested it in the browser and merged it. Along the way we checked whether Jest is used, ran the first `npm ci` in this clone, and looked into the `npm audit` findings (#36). Mid-session the developer also asked for a change to the test table's rules: only Red and Amber rows need attention, so only they are tinted, while Green keeps its pill.

**Discussion & decisions:**
- The developer asked for the decisions one at a time. Decided: the name is `<prefix>_GridFormatter.<table>.json`, with a dot after `GridFormatter` because table names can't contain one; the extension stays `.json`, because JSON isn't valid JavaScript and editors would flag a `.js` file; when two files match a table, warn and use the first alphabetically.
- I pushed back on the `/` (`pac solution unpack` turns it into ordinary folders), but the developer wanted it gone for Windows file names. The design works either way.
- The `wb_` prefix stays only on the control's own solution components (`wb_Controls.GridFormatter`, its environment variables); anything a project supplies is found under any prefix. That's ADR-0005's general rule, now enforced by `check:controls`.
- The lookup decision changed after the spike. We'd chosen "read the publishers' prefixes, then query exact names, with `endswith` as a fallback". The Basic User role can't read `publisher`, though, so ordinary users would always fall back. Measured on 20,782 web resources, `endswith` cost only about 0.1–0.2 s more, so the developer chose `endswith` alone, and ADR-0005 was revised the same day.
- `npm audit`'s six moderate findings are one `@opentelemetry/core` advisory, pulled in by Microsoft's `pcf-scripts` telemetry. Nothing reaches Dataverse and there's no clean fix, so the risk is accepted for now, and #36 tracks a recheck when `pcf-scripts` updates.
- The generic example files keep `wb_` column names, because the tests run them against rows captured from the `wb_gridspike` test table. The configuration guide tells makers to use their own columns.

**Discussion & decisions:**
- The skills came from RemoteScience (the newest install), then were refreshed with `npx skills add`. Only `chief-of-staff` had changed upstream. Setup chose GitHub Issues, the default triage labels, a single-context domain layout and `CLAUDE.md`.
- The brief was written for a standalone `wb-grid-formatting` repo with one solution. For a repo that will hold every WB control, the developer chose **one solution per control**, **npm workspaces with a shared package**, **per-control semver with `<Control>-v<x.y.z>` tags**, and **CI that builds and tests but doesn't deploy**. The reasoning is in ADR-0001 and ADR-0002. The brief now sits in `docs/briefs/`, with a note that its layout section is superseded.
- `pac solution init` writes a random option value prefix on every run, so one canonical publisher was fixed (`WilliamBuck` / William Buck / `wb` / 94879) and enforced in CI. The developer created it in the William Buck dev environment by hand, after first proposing a portal-generated 12763, which was changed to match the repo. UAT and prod have no `wb` publisher; the first managed import will create it. The prefix is confirmed final.
- The `LowCode` environment (https://lowcode.crm.dynamics.com/) in the developer's personal tenant is the test environment for spikes. It is **not** the WB tenant. The publisher was created there too, by importing and then deleting an empty unmanaged seed solution. The first build of that seed was accidentally managed and was rebuilt before importing.
- For the colour utilities, `normalizeHex` returns a branded `HexColor` and the other functions accept only that type. This keeps the brief's return types while ensuring nothing downstream throws on bad input. Two expected values in the tests had been written from memory and were wrong: #C50F1F on white is 6.07:1, and WCAG picks black text on Fluent blue #0078D4.
- TypeScript is pinned to 5.x because ts-jest doesn't support TS 7 yet. ESLint versions match the PCF template.
